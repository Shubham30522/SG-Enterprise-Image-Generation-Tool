  Yes, the reference image IS being passed to the API. Here's exactly how it 
  works:

  The Flow (end-to-end):

  1. Frontend Upload (Sidebar.jsx → App.jsx)
  - The user uploads a reference image via the sidebar UI
  - handleRefUpload() calls api.uploadReferenceImage(file) which POSTs to
  /api/upload/reference

  2. Backend Storage (server.py:401-416)
  - In Cloud mode (Supabase): The file is saved to Supabase Storage at
  _uploads/ref_<random>.jpg
  - In Local mode: Saved to input_images/_web_uploads/ref_<random>.jpg
  - Returns the path back to the frontend

  3. Generation Request (App.jsx:312-320)
  - When generating, the frontend sends reference_image_path in the JSON body:
  {
    "product": "Kurti Set",
    "sku": "Yellow",
    "reference_image_path": "_uploads/ref_abc12345.jpg",  // <-- this
    "match_pose": false,
    "match_bg": false,
    "provider": "gemini"
  }

  4. Image Assembly (server.py:884-897)
  - _run_front_generation() builds the input_images list:
    - Image 1 = Raw product image (from SKU folder, e.g. input_images/Kurti 
  Set/Yellow/front.jpg)
    - Image 2 = Reference image — either:
        - The uploaded reference (req.reference_image_path), OR
      - A fallback: any image file placed directly at the product level
  (input_images/Kurti Set/reference.jpg)

  5. API Call (api_client.py:95-118)
  - fetch_image_from_api() loops through ALL images in input_images and sends
  them as base64 inline data parts to Gemini — so both Image 1 (raw product) AND
   Image 2 (style reference) are sent together in the same API call.

  So where does the reference image go in your Supabase setup?

  Two options, both already work:

  Method: UI Upload (explicit)
  Storage Location: Supabase: _uploads/ref_<id>.jpg
  How it's used: User picks file in sidebar → passed as reference_image_path
  ────────────────────────────────────────
  Method: Product-level fallback (automatic)
  Storage Location: Supabase: input_images/<Product>/reference.jpg
  How it's used: _get_sku_images_cloud() auto-detects files with "reference" in
    the name at the product root

  The product-level fallback is the key convenience feature

  If you place a file named reference.jpg (or any image with "reference" in its
  filename) directly under input_images/<Product>/ in Supabase Storage — i.e.,
  NOT inside any SKU subfolder — it will automatically be picked up as Image 2
  for every SKU of that product, without the user needing to upload it each time
   through the UI.

  Your current prompts are already written correctly for this — they reference
  Image 2 (Style Reference) which maps to the second image in the list.

  Bottom line

  No code changes needed. The reference image flow is fully wired for both local
   and Supabase cloud. You just need to either:
  1. Upload via the sidebar reference image picker in the UI, or
  2. Place a file named reference.jpg in your Supabase bucket at
  input_images/<Product>/reference.jpg for automatic pickup across all SKUs.

  Bug 1 — Deleted product stays selected (App.jsx:119-131):
  - Before: loadInitialData only selected a new product when selectedProduct was
   empty/falsy. After deletion, it still held the deleted product name, so the
  condition was never true.

  checks if the current value still exists in the freshly-fetched product list.
  If it doesn't (because it was deleted), it auto-selects the first available
  product. If no products remain, it clears to ''.

  Bug 2 — Deleted SKU still shows in sidebar color dropdown (App.jsx:146-150, 
  185):
  - Before: handleBackToGeneration only called loadInitialData() which refreshes
   the product list. SKUs were only reloaded via a useEffect triggered by
  selectedProduct changes. If you deleted a SKU but the product didn't change,
  the stale SKU list persisted.
  - Fix: Added a detailsRefreshKey counter state. handleBackToGeneration
  increments it when returning from ProductManager. The useEffect that loads
  SKUs/poses now depends on both selectedProduct AND detailsRefreshKey, so it
  re-fetches even when the product hasn't changed.
